# Model selection and immutable provenance

Verified 11 October 2026. Use `qwen3_0_6b` for the current CPU FP32 engineering smoke test. Keep `qwen3_1_7b` as the provisional reference for the later scientific pilot on the RTX 2080 Ti in explicit FP16. Both are ordinary dense text decoders with the same 28-layer attention layout and explicit thinking-mode control. This choice prioritizes interpretable hooks and bounded mechanics; task competence and guided headroom remain unmeasured. The authoritative machine-readable records are [models.json](../../configs/models.json) and [source-evidence.json](source-evidence.json).

The Plan described future setup and did not itself execute it. This increment selects artifacts for the authorized implementation. It makes no inference-quality, scientific-discovery, throughput, or GPU-feasibility claim.

The alternative configurations and their own immutable revisions are retained in source-evidence.json. The comparison is scoped to relevant official candidates, not an exhaustive market ranking. Published benchmark superiority cannot establish a useful composition bottleneck on this study's worlds.

For both selected models, config declares 28 layers, 16 query heads, eight KV heads, head dimension 128, tied token/output embeddings, and no sliding window. The hidden/MLP dimensions are 1024/3072 and 2048/6144 respectively. Config's maximum positions are 40,960, while the official card explains 32,768 context plus 8,192 generation; tokenizer's much larger `model_max_length` is not a validated experiment limit. Start with short sequences. Inspect the installed Transformers module implementation before naming a residual site: block input, block output, attention output, and MLP output are different interventions. See the [pinned 0.6B config](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/config.json) and [1.7B config](https://huggingface.co/Qwen/Qwen3-1.7B/blob/70d244cc86ccca08cf5af4e1e306ecf908b1ad5e/config.json).

The larger Hub tensor counts are serialization counts, not unique model counts: 751,632,384 and 2,031,739,904 differ from the config-derived counts by exactly one embedding-sized tensor. The 1.7B index explicitly lists both `model.embed_tokens.weight` and `lm_head.weight`, while config ties them. The formula for unique parameters is embedding + 28 × (Q/K/V/output projections + three MLP projections + two layer norms + Q/K head norms) + final norm. Verify the actual unique count after loading/tie_weights. Raw unique-weight estimates are 1,192,099,840/3,441,149,952 bytes in FP16 and 2,384,199,680/6,882,299,904 bytes in FP32. They omit allocator and activation overhead. Both models' FP16 KV cache is 114,688 bytes per token at batch one. Serialized downloads remain larger because tied tensors are duplicated.

The source tensors are BF16. CPU FP32 conversion is an explicitly recorded engineering condition; the future Turing GPU condition is FP16. Neither inherits the other's numerical tolerances or performance. No quantization or alternative backend is silently substituted. The pinned cards require Transformers with Qwen3 support, at least 4.51.0; record the actual installed stack and verify the adapter on that stack.

Both selected tokenizer configs embed the same 4,168-byte UTF-8 chat template. Its extracted-string SHA256 is `a55ee1b1660128b7098723e0abcd92caa0788061051c62d51cbe87d9cf1974d8`; the complete source file SHA256 is separately recorded. The registry retains the exact template text. Pass `add_generation_prompt=True` and `enable_thinking=True` explicitly for the Plan's provisional substantive baseline. With `enable_thinking=False`, the template appends an empty think block. Preserve exact rendered prompts and token IDs. Tokenizer has no automatic BOS token; config BOS is 151643, generation pad is 151643, chat EOS is 151645, and generation settings stop on either 151645 or 151643. Do not conflate these fields. See the [pinned tokenizer config](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/tokenizer_config.json).

Thinking-mode starting sampling is temperature 0.6, top-p 0.95, top-k 20, min-p 0, with seeded sampling. Non-thinking starting sampling is 0.7/0.8/20/0. Record the actual mode, seed, complete settings, cap, stop reason, and truncation. A greedy or teacher-scored run can diagnose engineering invariants but cannot stand in for the Plan's thinking-mode behavioral baseline. Short capped traces can end before an answer; this is not evidence of a reasoning failure. See the [official 0.6B card](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/README.md).

The dated [official Qwen3 announcement](https://qwenlm.github.io/blog/qwen3/) is 29 April 2025. Repositories were created 27 April, but creation is not proof of public release. Initial weight-upload commits are 28 April, and official API comparisons show their weight hashes and config match the selected snapshots. Tokenizer JSON, merges, and vocabulary also match. However, both chat templates changed on 19 May. The selected revision commits on 26 July add LICENSE. These are different provenance events. Evidence and comparisons are retained from [0.6B history](https://huggingface.co/Qwen/Qwen3-0.6B/commits/main) and [1.7B history](https://huggingface.co/Qwen/Qwen3-1.7B/commits/main).

For a conservative audit of this complete selected artifact set, use 26 July 2025 as the snapshot date, with the limitation that commit timestamps plus a currently public repository do not cryptographically prove past public visibility. The April family announcement and identical weights support earlier weight lineage, but do not backdate the selected May template. If an item requires the April artifact set, pin the relevant historical revision and audit its exact template and historical public availability separately. No training-data cutoff is documented in the selected cards; the registry stores null rather than inferring one from release. Post-training is included in the checkpoint. Item-level eligibility additionally requires the target's earliest public disclosure, all supplied inputs, precursor/bridge leakage, and any hindsight assistance. A temporally eligible checkpoint's correct answer establishes neither novelty to science nor absence of other contamination.
